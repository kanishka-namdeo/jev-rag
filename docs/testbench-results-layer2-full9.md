## What this run says

**No arm beats `base` significantly.** Every FDR-adjusted q-value is 1.000. That is the
honest headline of the complete suite, and it is what the pre-declared power analysis
predicted: at n=98 pooled only effects of roughly 10–15 pp with ≥25 % discordance can reach
p<0.05, and the largest observed effect here is 6.1 pp.

The one comparison whose paired bootstrap CI excludes zero is `rerank-none` at
**+6.1 pp [−0.0, +12.2]** (McNemar p = 0.180). It is the only arm with a CI that does not
cross zero, and it points the wrong way from the v3 design assumption — see below.

## H-RERANK: the cross-encoder is not paying for itself end-to-end

| arm | reranker | correctness | Δ vs base | p50 latency | cost |
|---|---|---|---|---|---|
| rerank-none | none (RRF only) | **0.7194** | +0.061 | 73.6 s | $0.185 |
| base | cross-encoder | 0.6582 | — | 19.6 s | $0.161 |
| rerank-jev | jev noul | 0.6531 | −0.005 | 25.1 s | $0.180 |

This **contradicts Layer 1**, where RRF + cross-encoder was the best precision retriever
(hit@1 0.918, MRR@10 0.942) and jev noul was the weakest reranker. Two of the three readings
agree — jev rerank is not helping — but on end-to-end judged correctness, dropping the
reranker entirely scored highest.

The mechanism is visible in the escalation column. `rerank-none` escalates **100 %** of
questions: the features gate reads the top-1 cross-encoder score, so with no reranker that
feature collapses below θ and every question takes the hard path (its calibration row is
degenerate for the same reason — acc 0.0, Brier 1.0). So `rerank-none` is really
"RRF-only retrieval + always escalate", and that combination beat both `base` (+6.1 pp) and
`always-hard`, which is "cross-encoder + always escalate" (+0.5 pp). The implied reading is
that the cross-encoder's top-4 selection is throwing away passages the decompose-and-retrieve
hard path could have used.

That is a hypothesis, not a conclusion: it rests on one comparison at p = 0.18, and it costs
3.75× median latency. The follow-up that could actually settle it is a rerank-none vs
always-hard paired comparison restricted to the questions where they disagree, plus a
recall@4 check on the same subset.

## H-GATE: the marginal value is smaller than M11 reported, and not stable

base 0.6582 vs gate-none 0.6327 is **+2.5 pp** for escalating at all (M11 reported +4.6 pp).
`oracle-gate`, the perfect-retry ceiling, came in at **+2.5 pp** — M11 measured it at
**−3.6 pp**. The gate's own calibration is good: accuracy 0.878, Brier 0.106, ECE 0.150,
and a 12.2 % false-negative rate on answerable questions (unnecessary escalations).

`gate-jev` — the v2 absolute-sufficiency gate this project moved away from — scored 0.699
(+4.1 pp, p = 0.302), the second-best arm overall, while being by far the worst-calibrated
decision in the suite: accuracy 0.633, Brier 0.314, ECE 0.448 at its own θ = 0.5. It is also
the only arm that improves accuracy *and* stays cheaper than `base` ($0.1602 vs $0.1614),
though at 1.58× latency.

## Caveats and confounds

- **Run-to-run variance is ±3 pp on these comparisons**, and larger on `oracle-gate` — see
  the reproducibility table below. Any single run of this suite is one draw.
- The judge is `kimi-k2.5`, a different model family from the `qwen3.x-plus` generators, so
  self-preference bias is structurally limited but not zero.
- `escalation_rate` for `gate-jev` is derived from a probability against θ = 0.5, while the
  other arms record a literal `escalate`/`easy` verdict. The analyzer had to be fixed to
  read the jev shape at all (it previously reported a structurally impossible 0 %).
- Public scenarios are all answerable, so `FP(unans)` is undefined throughout and the gate's
  fabrication-risk side is untested here — the internal `outofscope` scenario covers it.
- Latency and cost are cloud-endpoint dominated, so they carry the endpoint's own variance.
- **2026-10-01 — the shipped default now matches this page's θ.** `app/config.py`'s
  `gate_score_threshold` moved 0.5 → 0.6 to match `backend/.env.example` and the gate
  calibration tables above, so a user who never copied the template runs the gate the published
  tables describe. Do-no-harm smoke (`db23b949`, `outofscope` only, 8 questions, both arms,
  throwaway data dir): completed with **0 error rows**, both arms 8/8 correct, hybrid abstained
  on the five out-of-scope questions with zero fabrications — within one question of the
  `bf05f585` baseline recorded in `benchmark-results.md`. At n=8 this has no statistical power
  for a delta this small; it makes the shipped default and the published calibration agree in
  writing, not a new inference result.
